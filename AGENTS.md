# AGENTS.md

Contract sheet for coding agents: standing rules in present tense; full mechanics and rationale live in `docs/invariants.md` and linked owning docs. Keep strictly under 24 KB (`node scripts/check-contract-size.mjs`). `CLAUDE.md` imports this file with `@AGENTS.md` (single source). Release history lives in `CHANGELOG.md`, never here.

## Quick reference

- Version: 3.1.2 (`kimi-code`, subprocess transport, native agent-core-v2).
- Native-v2 safety (§1): every executed tool passes managed PreToolUse; the plan-file allow is never armed. At 2.8.0 upstream runs the external hook before the plan guard with zero `event.allow()` callers, while all four no-plan closures stay mandatory on every release: (1) same-child-home preflight refuses every normalized `default_plan_mode` spelling except non-swarm launches of exact `print-cancels-plan` rows, where fresh print cancels it; (2) hook denies `EnterPlanMode`/`ExitPlanMode` for every label; (3) resume requires proven `native-v2` lineage, every-agent raw journal plan-taint scans tolerating only that cancelled create-time pair (allowing only Kimi's 3 durable MCP bookkeeping records between enter and cancel), and refuses active tower mode (`KIMI_SESSION_TOWER_ACTIVE`); (4) per-flag env forces `KIMI_CODE_EXPERIMENTAL_TOWER=0` and `KIMI_CODE_EXPERIMENTAL_SUBAGENT_FORK=0` in every child, drops `KIMI_CODE_EXPERIMENTAL_FLAG`, and uncertified releases warn about enabled selectors. Local execution is mandatory: `environments.default` refuses except non-swarm exact `local-environment` launches (fresh: `--environment local`; resume: stored local binding); `require_trust = false` only warns; resumed nonlocal or wrong-root bindings and launcher environment selectors refuse. Require exact-version first-line `system.version`, validate `Bash.cwd` against trusted root, and require source scan, plan-ON control, and per-operation smoke per certification row.
- Hook-pin durability (§1): canonical hook commands avoid version-stamped Node tokens; `process.argv0` is eligible only when absolute and `realpath`-identical. `verifyHookInstalled` fail-closed checks the parsed-back Node token with `access(X_OK)` and script readability. Re-pin recovery runs only when `retryable_after_setup` is literally `true` and setup exits 0, then retries once. Active `KIMI_PLUGIN_CC_DATA` against the default canonical hook sets `retryable_after_setup: false` and advises unsetting it and restarting. `node-bin-not-executable` requires repairing Node; in-verifier auto-repin is rejected.
- Test discipline (§1): detached-worker enforcement tests run a real `node` subprocess through a symlink, without `KIMI_PLUGIN_CC_NODE_BIN` or `KIMI_PLUGIN_CC_SKIP_HOOK_CHECK`. Host-dependent smoke asserts its precondition; never test a never-armed plan-file allow as active.
- Upstream compatibility (§2): rolling window `>= 2.8.0`, exact and per-operation in `runtime/kimi-releases.ts`. Exact `2.8.0` is certified for all 7 model operations (`ask`, `review`, `challenge`, `rescue`, `pursue`, `swarm`, `swarm-write`) with bounded swarm (`docs/upstream-2.8.0-certification.md`). `NATIVE_V2_CERTIFIED_VERSIONS` is the all-operation export; `NATIVE_V2_ANY_OPERATION_VERSIONS` is the scoped union. Unlisted plain `2.y.z > 2.8.0` runs read-only (`ask`, `review`, `challenge`) with a warning, borrowing only `--environment local`; write/swarm, `--network`, pre-release/build suffixes, other majors, and all ops under `KIMI_PLUGIN_CC_STRICT_VERSIONS=1` refuse. Releases `< 2.8.0` and `legacy-v1` are removed and refuse before spawn (historical SQLite rows stay readable only). Audits re-verify all surfaces (`docs/upstream-compat-audit.md`) and §2; monitor reports never certify.
- Toolchain: Node `>= 22.5` (`>= 24.9` for DSH), TypeScript, `bun` for dev; `npm` only for registry operations and package installs.
- Installed-state verification: run `kimi_setup({ action: "check" })` or the active install's `scripts/companion.sh setup --check`; a checkout proves nothing about an installed host.
- Kimi binary (§5): jobs pick `KIMI_PLUGIN_CC_KIMI_BIN`, then plugin-owned `<pluginRoot>/kimi-bin/current` (executable regular file inside `kimi-bin/<x.y.z>/`), then `kimi` on `PATH`. Only `setup --install-kimi` (or `kimi_setup` `install_kimi`) installs or uses the network, shared across hosts.
- Credential-bearing config (§3): never routinely read, print, copy, or retain `~/.kimi-code/config.toml` or `~/.kimi-code/credentials/`; use sanitized `setup --check` or `setup --models [--json]` (or `kimi_setup`). Explicit config diagnosis covers only the managed hook block with credentials redacted; credentials are never read or copied.

## Commands

- `bun run check` — build, contract-size gate, generated-surface checks, typecheck, full tests, and drift gate for `dist`, `plugins/kimi-codex`, `dsh/index.json`, and `cordis.patch.yml`; stage generated outputs and retry when asked.
- `bun test <path>` — run one test file.
- `bun run build` — compile `runtime/**/*.ts` to `dist/**/*.js` and bundle self-contained ESM `dist/hooks/approval-hook.js` (zero relative imports).
- `bun run generate:surfaces` — regenerate `plugins/kimi-codex/`, `cordis.patch.yml`, and `dsh/index.json`.

Companion CLI (`scripts/companion.sh <subcommand>` -> `dist/companion.js`): 5 primary subcommands (`read`, `write`, `job`, `setup`, `mcp`), plus compatibility aliases (`ask`, `review`, `task`, `status`, `result`, `cancel`, `replay`, `recover-swarm`, `repair-sessions`) and internal `worker` / `mcp-child`.

## Architecture

Thin universal connectors, single runtime:

- Connectors route only; runtime owns subprocesses, SQLite jobs, approval policy, and rendering.
- MCP: `host MCP client -> companion.sh mcp -> supervised mcp-child -> execution plan, job store, artifact`.
- CLI: `companion.sh <read|write|job|setup> -> companion.js -> kimi -p --output-format stream-json -> job store -> artifact`.
- No slash commands (`commands/`), subagent files (`agents/`), `review_gate` hook, or custom DSH runtime (`runtime/dsh/`, `plugins/kimi-dsh/`).

Standing invariants (full statements in `docs/invariants.md` §4 unless linked otherwise):

- Subprocess-first: one `kimi -p` runner per job; certified parallel swarm waves add only bounded `web --json` activation (§2). Dual-source first-announce-wins session-id capture, pinned and idempotent, meta filtered from `records[]`; ids round-trip via `kimi -r`.
- Swarm execution roots (§2): real paths use canonical execution cwd for activation/resume, print, trusted-root checks, and read-mode preflight. Recovery canonicalizes `record.cwd` only for deactivation, retaining its alias for ownership/patch checks. Bounded `2.8.0+` rows use ephemeral-token `web --json` + direct WebSocket subscribe only for parallel waves; concurrency 1 starts one direct worker.
- Collapsed surface and routing: 4 MCP tools (`kimi_read`, `kimi_write`, `kimi_job`, `kimi_setup`) + full `SEP-2640` (`skills/list`, `skills/get` returning `frontmatter` and `resources` SHA-256 digests/sizes for `SKILL.md` and `agents/openai.yaml`, plus `resources/list` and `resources/read`, with `ttlMs: 0`/`cacheScope: "private"` on `2026-07-28`). Standard `tools/call` on `kimi_read`/`kimi_write` defaults to `wait: true` with a 50 s default `wait_timeout_ms` (max `86_400_000`; client disconnect/cancel stops polling without cancelling the durable job); `wait: false` always returns the launch handle even if already terminal. Primary CLI has 5 subcommands (`read`, `write`, `job`, `setup`, `mcp`); `read` rejects leading `--write`, negative numbers (`-5`) start prose, and `routeSurfaceAliases` reads `--mode` (and legacy `ask --write`/`review --challenge`) from leading flags only. MCP prompts always follow `--`.
- MCP transport and ownership: modern `2026-07-28` calls with per-request `io.modelcontextprotocol/tasks` return native task handles (`tasks/get`, `tasks/cancel` — both require an `mcp_tasks` row); legacy/non-tasks calls use `wait` + `kimi_job` (`idempotentHint: false`). Fixed task/job UUIDs, bounded 60 s attach (a job settled before identity probe attaches), pinned data root and `KIMI_CODE_HOME`, strict canonical workspace containment (no cross-workspace monorepo listing or cross-repo stale sweeps), JSON-only stdout, identity revalidation (including persisted CLI identities for MCP `cancel`), and reconnect-by-ID are mandatory. Disconnects never cancel; `jobs` owns outcomes and failed jobs return `isError: true` with artifacts. `kimi_job` runs `list|status|result|wait|cancel|replay|recover_swarm` (ID-less `wait` pins resolved `job_id`; `replay` includes outcome/partial/`isError`); `instructions` cite `skill://kimi/SKILL.md`, write tools, `wait`, and warning relay.
- Universal five-host packaging: Claude Code (`.claude-plugin/`, `.mcp.json`, `skills/kimi/`), Codex (`.agents/`, generated `plugins/kimi-codex/`), Antigravity (root `plugin.json`, `mcp_config.json`, `assets/logo.svg`, `skills/kimi/`), DSH (root `cordis.patch.yml` via `@deepseek-ai/dsh-mcp-client` and `@deepseek-ai/dsh-skill-filesystem`, plus `dsh/index.json`; requires patched host/profile `zod >=4.6.6` and `undici >=8.12.2`), and Magpie (local MCP server invoking `scripts/companion.sh mcp`). All share one data root and one hook.
- Prompt and metadata separation: raw task text owns summaries, titles, and previews; full prefixed prompts own spawn, digest, and recovery. Working-tree review includes untracked files; `--base` never treats dirty files as committed snapshots. Pursue uses `/goal --`, enforces the 4,000-char objective limit including hints, and denies `SetGoalBudget`.
- Managed hook enforcement: all 7 model ops require the canonical PreToolUse hook and refuse before spawn when verification fails; execution plan rechecks before any job row. Labelled calls undecided at 10 s deny (upstream timeout reads as allow). Every label allows `WaitFor`. `KIMI_PLUGIN_CC_SKIP_HOOK_CHECK=1` is a tests/diagnostics bypass only, never a repair path or v2-preflight bypass.
- Hook-escape monitor (§1): denied streamed calls whose result is not the managed denial (exact or with repeat-breaker `<system-reminder>` blocks) record `mismatch`; absent results record `unresolved`. Detection evidence only, never failure; exposed via logs, `hook_escapes`, status/result/stderr, and timeout details. Never fail a job without positive execution evidence.
- Exact hook verification: rebuild canonical command bytes; parse complete TOML with vendored `smol-toml@1.9.1`; validate every hook entry and managed grammar; every copy needs `timeout >= 15` s. Additive events (`PermissionRequest`, `PermissionResult`, `Interrupt`) require an exact certified `>= 2.8.0` `hook-schema` row. When `KIMI_PLUGIN_CC_HOOK_SCRIPT` is unset, `verifyHookInstalled` and `setup --check` reject symlinked managed `hook/`/script paths and verify installed `<pluginRoot>/hook/approval-hook.js` SHA-256 against bundled `dist/hooks/approval-hook.js` (mismatch surfaces `retryable_after_setup: true` / failed check). Absent-state fallback accepts a real-parser-proven clean enforcing table with byte-exact command, no matcher, and no extra keys; with that proof, job-time duplicate/orphan markers warn while `setup`/`--check` fail. Never substitute line scanning.
- Serialized config mutation: private adjacent lock (`0600`) across read-modify-write and hook publication; atomic `0600` config write, `0700` home. No-follow/nonblocking/regular-file capped reads, bounded acquisition, no live-owner theft, ABA-safe stale recovery, inode/token rechecks. Normalize inline `hooks = [...]` (including on uninstall); remove only lexically proven orphan marker comments with warnings; refuse (`SETUP_INVALID_HOOKS_CONFIG`) rather than deleting paired blocks containing extra tables; preserve surrounding bytes and foreign hooks. `setup`/`--check` fail on any remaining config, schema, block, path, SHA-256, or probe failure.
- Single bundled ESM hook and canonical block: `setup` validates `pluginRoot`/`hook/` against symlinks, stages candidate `dist/hooks/approval-hook.js` + `package.json`, and runs `probeHook` BEFORE activating `<pluginRoot>/hook/approval-hook.js` (dir `0700`, files `0644`, preserving working hook on failure) unless `KIMI_PLUGIN_CC_HOOK_SCRIPT` is set, then writes one `# === BEGIN kimi-plugin-cc-managed (v3.1.2) ===` ... `# === END kimi-plugin-cc-managed ===` block. `setup` consolidates legacy `:<host-id>` blocks and prunes only exact known install layouts (`isOurApprovalHookCommand`), never custom or hand-rolled hooks. `setup --uninstall` normalizes inline hooks, removes canonical/legacy blocks, orphans, and strictly owned bare tables, and confirms removal (`--all` removed from uninstall).
- Rescue write policy: rescue, pursue, and write-swarm share `evaluateRescueHookRequest`: shell-quote parsing, 16,384-char cap, mutating/output/exec-flag detection, symlink/realpath/hard-link containment, and report-writer rejects. `rm`/`mv`/`cp`/`mkdir` allowed with exact flags on absolute in-root non-`.git` operands, never on Windows; one per command; recursive/dir sources refuse `.git` trees (bounded 20,000-entry / 3 s scan); `.git` matches any case or trailing dots/spaces; ambiguous spellings refuse. Test runners run repo code by design; internal Git context retains the trust boundary in `docs/safety.md`.
- No Git mutation: rescue, pursue, and write-swarm never mutate Git state; calling host owns branches and commits.
- Pursue (experimental): runtime-foreground-only `/goal --` with rescue policy and hook on every turn; no Git mutation or resume; finite 45m default budget. Trusted pursue/root allows exact `GetGoal {}` and terminal `UpdateGoal { status: "complete" | "blocked" }`; creation, reactivation, and budget mutation stay denied. Preserve rescue lineage, immutable operation export, and exits 0/3/6.
- Read-only swarm: workers keep read-only hook; singular `Agent` denied. Default 30m finite budget; `--cap` is a soft total hint. Bounded rows (`2.8.0+`) bound simultaneous Kimi child turns (not coordinator/OS subprocesses) by `--max-concurrency` (default 4). Hook counts fresh + resumed entries; malformed calls, forks, and fresh singleton waves deny. Concurrency 1 runs one direct worker with delegation denied. `KIMI_CODE_SWARM_TIMEOUT_MS=2147483647` overrides ambient values. Parallel sessions disable native `TaskStop` after activation shutdown and before print; hook denies explicit background Bash. Identity-verified settlement gates exit and cancellation before capture.
- Write-swarm is patch-only: born-HEAD detached worktree under `<pluginRoot>/worktrees/` holds writes while `job.cwd` stays user workspace; trusted root confines them and disjoint targets stay prompt guidance. Require hooks, finite budget, and dirty-tree warning. Default concurrency 1 is a direct worker; higher values use guarded waves. Capture untruncated binary patch before cleanup; capture/cleanup failure retains tree. Never apply, commit, or age-delete; prefer explicit cancel. Pursue writes real workspace.
- `goal.summary` and retry metadata: capture role-less `goal.summary` on `CliClientResult.goalSummary`; filter `turn.step.retrying` as wrapper metadata; malformed shapes enter diagnostics.
- Canonical shared plugin data root (§5): `KIMI_PLUGIN_CC_DATA` is the strict absolute override; else `$XDG_DATA_HOME/kimi-plugin-cc` (relative `XDG_DATA_HOME` ignored per XDG spec) or `~/.local/share/kimi-plugin-cc` on POSIX, `%LOCALAPPDATA%\kimi-plugin-cc` on Windows. Plugin-owned dirs (`pluginRoot`, `logs/`, `artifacts/`, `hook/`) use `0700` and stream logs use `0600` (POSIX). All hosts share `state.db`, `logs/`, `artifacts/`, `hook/`, `worktrees/`, `kimi-bin/`. No auto-migration from 3.0 per-host dirs; detached workers pin `KIMI_PLUGIN_CC_DATA`.
- Authoritative SQLite jobs: terminal states are permanent. Nullable response budgets and `budget_source` track explicit/inherited/default for ask/rescue/review/challenge; pursue/swarm persist effective ceilings. Detached workers reload budgets from SQLite; inherited ask/rescue budgets print at launch.
- Session visibility and titles: settled native-v2 sync sets preview to raw request (redacted, <= 4,000 chars, non-empty) and invalidates shared index; preserve manual/native titles and replaceable fallback semantics. Never auto-invoke native title endpoint. `setup --repair-sessions` / `kimi_setup` `repair_sessions` previews by default, writes only with `--apply` after prompt-digest match, and replaces only blank or own-prompt previews (`docs/session-visibility.md`).
- Model selection: `--thinking` sets `KIMI_MODEL_THINKING_EFFORT`; omission preserves ambient env and resumes do not inherit; honoring is unobservable over stream-json. Omit `-m` for defaults; resumes keep session model; aliases never change saved defaults. `setup --models [--json]` is a credential-safe inventory; never guess aliases or fall back silently (`docs/models.md`).
- Per-call scope: only ask, review, challenge, and read-only swarm take `--read-root <abs-dir>` and `--network` (MCP `read_roots`/`network`). Hook reads only per-spawn `KIMI_PLUGIN_CC_READ_ROOTS`/`KIMI_PLUGIN_CC_NETWORK`, deleted before every spawn; malformed values fail closed. `--network` allows public-host web tools and confines reads to workspace + roots; refuses on uncertified releases and resumes with unconfined history. Scope is never inherited.
- Session references: `--reference-session <id>` (MCP `referenced_sessions`, <= 8) on ask/review/challenge/rescue/swarm appends exact `<referenced_sessions>` block naming each main journal without reading content. Unknown, ambiguous, or unsafe ids and the resumed session refuse before any job row. Scoped calls gain each session's `agents/main` as a read root. Never on pursue, nor in summaries, titles, or previews.
- Prose pass-through and LLM-caller discipline: model ops emit raw prose; stderr is for humans, load-bearing outputs use stdout, exit codes, or SQLite. Unknown flag-shaped tokens fail `INVALID_ARGS`; leading `--help` prints usage and exits 0. `RuntimeError.details` carries structured context; CLI errors stay bounded diagnostics. `job result <id> --json` exposes envelope, budget provenance, and session id/source. Launch warnings persist in `warnings` and open stdout/artifacts as `Warnings:`; warning-free output is unchanged.
- Cancellation: AbortController + SIGTERM -> SIGKILL (1,500 ms), teardown as settlement barrier. Revalidate PID/PGID/start identities, confirm bounded quiescence, never signal replacements, emergency-kill owned root on teardown failure; Windows is direct-child-only. Snapshot failure stops owned root then fails with unverified cleanup + cause; wrapped budgets keep no partial prose. Budgets <= 24h, unaffected by backgrounding. Clean non-aborted exit-0 wins same-tick expiry. Only budget timeouts retain partial prose and proven/recovered session; cancel never captures partial output. Preserve `settled_post_abort`, recovery, and lineage gates.
- Durable swarm recovery: record launch intent and verified identities before enabling swarm; store no tokens. On POSIX, a print root never identified settles only on its own exit, closed pipes, an empty group and a complete empty pass. `job recover-swarm` / `kimi_job` `recover_swarm` previews by default; `--apply` recovers only current repo's stopped owner after identity/session revalidation with recorded binary still selected, capturing without applying or deleting worktree. Terminal outcomes never change; abandoned running jobs fail. Never delete orphans by age (`docs/swarm-recovery.md`).
- Spawn diagnostics: preserve structured process causes; never turn E2BIG/ENOMEM/EMFILE into reinstall advice. Windows rejects overlimit UTF-16 argv with `CLI_COMMAND_LINE_TOO_LONG` omitting prompt. Print prompts stay argv-backed.

## When editing

- Read the runtime before changing it; safety invariants are not obvious from file names.
- Run `bun run check` before considering a change done.
- After `runtime/**`, `skills/**`, or `scripts/companion.sh` changes, run `bun run build && bun run generate:surfaces`, then stage `dist/`, `plugins/kimi-codex/`, `cordis.patch.yml`, and `dsh/index.json`. Never hand-edit generated files.
- `check:surfaces` checks pinned root hashes, Codex/DSH generated text, byte-exact runtime mirrors, self-contained `dist/hooks/approval-hook.js`, and no orphaned or sync-conflict files. Re-pin `CLAUDE_SURFACE_HASHES` with `shasum -a 256 <file>` on root surface changes.
- Tests never inherit host plugin env: `bunfig.toml` preloads `tests/helpers/preload.ts` to clear host root/data and overlays (`KIMI_PLUGIN_CC_TEST_NO_DEFAULT_DATA=1`); never remove the preload.
- Comments state current constraints and change with behavior; history belongs in `CHANGELOG.md`.
- Changing a contract requires updating both `docs/invariants.md` (full) and this file (short summary).

## Releasing

Plugin versions use SemVer and may align with a certified kimi-code version, never as compatibility evidence; state exact certified versions separately. Never reuse a published version/tag or use leading-zero patches. Source audit, exact-binary controls, per-operation smoke, and full check are mandatory ([docs/invariants.md §2](docs/invariants.md)).

`runtime/version.ts` is the single version source; `scripts/surface-registry.ts` propagates it to Codex and DSH outputs. A version bump touches:

- `runtime/version.ts`, `package.json`, `plugin.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`; re-pin hashes in `CLAUDE_SURFACE_HASHES`.
- `scripts/surface-registry.ts`: update `DSH_PUBLISH_TIMESTAMP`; `generate:surfaces` refreshes `dsh/index.json` and `cordis.patch.yml`.
- `AGENTS.md`: bump version and replace changed standing contracts in present tense.
- `CHANGELOG.md`: add a version section for releases, not docs-only checkups.
- Run `bun install --frozen-lockfile`, `bun run build && bun run generate:surfaces`, stage generated outputs, and run `bun run check`. Compiled-runtime regressions must run emitted JavaScript.

Commit and push, wait for CI, then `git tag -a vX.Y.Z -m "..."`, `git push origin vX.Y.Z`, and `gh release create --verify-tag`. Published tags are immutable; fix forward.

### npm distribution

`package.json` allowlists published files. `bun run check:package` packs the archive, rejects sync-conflict copies, verifies compiled/generated surfaces, boots DSH on `cordis.patch.yml` (4 `kimi_*` tools + `kimi` skill), and runs isolated setup/check, version-floor, and MCP smokes without credentials. CI runs it after `bun run check`; `publish.yml` publishes release tags via npm OIDC ([docs/ci.md](docs/ci.md#npm-oidc-publishing)).
