# AGENTS.md

The **contract sheet** for coding agents: standing rules in present tense; mechanics and rationale live in `docs/invariants.md` and linked owning docs. Keep it under 24 KB. `CLAUDE.md` imports it with `@AGENTS.md`: one source, nothing to mirror. Release history lives in `CHANGELOG.md` and `ROADMAP-TO-GA.md`, never here.

## Quick reference

- **Version**: 3.1.0 (kimi-code, subprocess transport, **native agent-core-v2**).
- **Native-v2 safety** (§1): every executed tool passes managed PreToolUse; the chain-breaking plan-file allow is NEVER armed. Preserve all four closures: same-child-home preflight refuses every normalized `default_plan_mode` spelling except on non-swarm launches of exact `print-cancels-plan` rows, where print cancels it; Enter/ExitPlanMode is denied for every label; resume requires proven native-v2 lineage and every-agent raw journal plan-taint scans that tolerate only that cancelled pair, and refuses a session left in tower mode; per-flag env forces tower and subagent fork off in every child, native-v2 children never get the master flag, and an uncertified release warns about enabled selectors. Local execution is mandatory: `environments.default` refuses except on non-swarm exact `local-environment` launches (fresh: `--environment local`; resume: stored local binding); `require_trust = false` only warns; resumed nonlocal or wrong-root bindings and launcher environment selectors refuse. Require the exact-version first-line marker, validate Bash.cwd against the trusted root, and require source, plan-ON control and per-operation smoke evidence per certification row. Legacy-v1 never gains 0.42.
- **Hook-pin durability** (§1): canonical hook commands avoid version-stamped Node tokens; `process.argv0` is eligible only when absolute and realpath-identical. `verifyHookInstalled` fail-closed checks the parsed-back Node token with `access(X_OK)`. Re-pin recovery runs only when `retryable_after_setup` is literally true and setup exits 0, then retry ONCE. `node-bin-not-executable` has a different remedy; in-verifier auto-repin is rejected.
- **Test discipline** (§1): detached-worker enforcement tests use a real node subprocess through a symlink, without `KIMI_PLUGIN_CC_NODE_BIN` or `KIMI_PLUGIN_CC_SKIP_HOOK_CHECK`. Host-dependent smoke asserts its precondition; never test the never-armed plan-file allow as though it were active.
- **Upstream compat** (§2): certification is EXACT and per-operation: one row per release in `runtime/kimi-releases.ts`; legacy-v1 ends at 0.41.x for a pinned binary. Exact 2.6.0 remains non-swarm-only. Exact 2.6.2, 2.6.3, 2.7.2, 2.7.3 and 2.8.0 (the **bounded rows**) are certified for all eight operations with bounded swarm (below); evidence: `docs/upstream-<version>-certification.md`. Older full-operation rows through 2.5.3 keep their recovery limitation. `NATIVE_V2_CERTIFIED_VERSIONS` is the all-operation export; `NATIVE_V2_ANY_OPERATION_VERSIONS` is the scoped union. An unlisted plain 2.x above 2.0.0 runs ask/review/challenge/review_gate uncertified with a warning, borrowing only `--environment local`; write and swarm operations refuse, as does everything under `KIMI_PLUGIN_CC_STRICT_VERSIONS=1`. The plan-file Write bypasses hooks through 2.7.3 and reaches them at 2.8.0; every no-plan closure stays mandatory on every row. Each audit re-verifies all surfaces (`docs/upstream-compat-audit.md`) and §2; monitor reports never certify. Activation, identity/quiescence, child-journal correlation and real rescue/Bash.cwd controls follow `docs/native-v2-status.md`.
- **Toolchain**: Node >=22.5 (>=24.9 for DSH), TypeScript, **bun** for development; npm only for registry operations and package installs.
- **Installed-state verification**: resolve the host's active version-stamped install cache and run its bundled `scripts/companion.sh setup --check`. A checkout, package metadata or another host's cache proves nothing about it.
- **Kimi binary** (§5): jobs use `KIMI_PLUGIN_CC_KIMI_BIN`, then plugin-owned `kimi-bin/current` (an executable inside `kimi-bin/<x.y.z>/`), then PATH `kimi`. Only `setup --install-kimi` installs or uses the network, per host.
- **Credential-bearing config** (§3): never routinely read, print, copy, or retain `~/.kimi-code/config.toml` or `~/.kimi-code/credentials/`; use sanitized `setup --check` or `setup --models [--json]`. Explicit config diagnosis covers only the managed hook block, credentials redacted; credentials are never read or copied.

## Commands

- `bun run check` — build, contract-size gate, generated-surface checks, typecheck, full tests, then the drift gate for `dist` and both `plugins/` trees; stage generated changes and retry when it asks.
- `bun test <path>` — run one test file.
- `bun run build` — compile `runtime/**/*.ts` → `dist/**/*.js`.

The companion runs via `scripts/companion.sh <subcommand>` → `dist/companion.js`. Subcommands: `setup`, `review`, `task` (`rescue`, `challenge`, `pursue`, `swarm`), `ask`, `status`, `result`, `cancel`, `replay`, `repair-sessions`, `recover-swarm`, `mcp`.

## Architecture

**Thin hosts, rich runtime**, mirroring codex-plugin-cc:

- Host surfaces route only; runtime owns subprocesses, SQLite jobs, approval policy, and rendering.
- Commands: `slash/skill → companion.sh → companion.js → kimi -p --output-format stream-json → job store → artifact`.
- MCP: `tool call → companion.sh mcp → supervised mcp-child → the same execution plan, job store, and artifact`.
- DSH: `native provider → managed subprocess → dist/companion.js → the same execution plan, job store, and artifact`; no ACP transport.

**Key invariants** (full statements in docs/invariants.md §4 unless linked otherwise):

- **Subprocess-first.** One `kimi -p` runner per job; certified swarm jobs add only the bounded activation lifecycle (§2). Session-id capture is dual-source, first-announce-wins, pinned and idempotent, with meta filtered from `records[]`; ids round-trip through `kimi -r`.
- **Swarm execution roots (§2).** Real command paths use canonical execution cwd for activation/resume, print, trusted-root checks and read-mode preflight. Recovery canonicalizes `record.cwd` only for deactivation, retaining its alias for ownership/patch checks. Bounded rows use authenticated direct-subscription activation only for parallel waves; concurrency 1 starts a fresh direct worker. Exact 2.6.0 swarm activation/recovery stays candidate-only.
- **Host surfaces.** Claude Code has four model commands and agents (task, review, pursue, swarm), Codex nine skills, MCP six model tools plus three job tools, DSH seven providers; all run the same seven operations. The runtime routes `ask --write` to rescue and `review --challenge` to challenge only from leading flags, never prompt text or anything after `--`; MCP prompts always follow `--`.
- **MCP transport and ownership.** Tools use per-request tasks capability; Codex legacy gets ordinary results, not native tasks. Fixed task/job UUIDs, bounded attachment (a job settled before its identity probe attaches), pinned data root/workspace, JSON-only stdout, identity revalidation and reconnect-by-ID are mandatory. Disconnects never cancel; `jobs` owns outcomes and failed jobs return `isError:true` with artifacts. `kimi_review` `mode` selects challenge; `instructions` name write tools and ask callers to relay warnings.
- **DSH native providers.** Seven providers keep the other hosts' write boundaries, plus `/kimi-setup`, `/kimi-status`, `/kimi-result`, `/kimi-cancel`. DSH pins host id `dsh` and an explicit data root; provider-owned env clears other-host and bypass overlays. Prompts follow `--`; profile model/thinking/budget/review-base options precede them. Only complete successful stdout reaches the parent; failures are bounded diagnostics; disposal awaits managed-range quiescence. Setup never runs implicitly; activations have no parent context, follow-up input, or per-call model overrides. DSH services/tool adapters are optional host-provided peers. DSH needs a patched host and profiles; package validation audits both and boots that host (docs/registry-releases.md).
- **Prompt and metadata separation.** Raw task text owns summaries, titles and session previews; full prefixed prompts own spawn/digest/recovery. Working-tree review includes untracked files; `--base` never treats dirty files as committed snapshots. Pursue uses `/goal --`, enforces the 4000-character objective budget including hints, and denies `SetGoalBudget`.
- **Managed hook enforcement.** Every model-spawning command requires the canonical PreToolUse hook; ask/review/challenge/rescue/pursue/swarm refuse before spawn when verification fails, and the review gate skips visibly; the plan rechecks before any job row. A labelled call undecided at 10 s denies (timeout reads as allow). Every label allows `WaitFor`. `KIMI_PLUGIN_CC_SKIP_HOOK_CHECK=1` is a tests/diagnostics bypass only, never a repair path or a v2-preflight bypass.
- **Hook-escape monitor** (§1): denied streamed calls whose result is not the managed denial record `mismatch`; absent results record `unresolved`. Findings are detection evidence, never failure, exposed through logs, `hook_escapes`, status/result/stderr and timeout details. Never fail a job without positive execution evidence.
- **Exact hook verification.** Rebuild canonical command bytes; parse COMPLETE TOML with vendored smol-toml@1.9.1; validate every hook and the managed grammar; each copy needs `timeout` ≥15 s. Markers are not durable: the absent-state fallback accepts a real-parser-proven clean enforcing table with byte-exact command, no matcher and no extra keys; with that proof, job-time duplicate/orphan markers only warn, while setup/check fail. Never substitute substring/line scanning; pruning stays conservative and host-scoped.
- **Serialized config mutation.** Hold the private adjacent lock across read-modify-write; publish atomically. No-follow/nonblocking/regular-file capped reads, bounded acquisition, no live-owner theft, ABA-safe stale recovery, inode/token rechecks, home 0700, config/lock 0600. Normalize inline hooks; remove only lexically proven orphan marker comments, with warnings, across hosts if needed; preserve surrounding content and every other host's hook. Setup/check fails on any remaining config, schema, block, path, or probe failure.
- **Host-scoped managed blocks.** Claude Code, Codex, and DSH share config.toml but own separate host-id blocks; DSH pins `dsh`. Install/uninstall is per-host and exact, prunes only strictly owned marker-less hooks, never hand-rolled ones; `--uninstall --all` is the sole every-host sweep. Kimi runs every block and any deny wins; every installed hook enforces every labelled job, and older other-host hooks warn. New blocks go right after the last managed END, keeping blocks contiguous; another host's orphan marker warns but never fails this host, while own/legacy orphans fail setup/check; the orphan remedy is plain setup, never scoped uninstall.
- **Rescue write policy.** Rescue and pursue share `evaluateRescueHookRequest`: shell-quote parsing, mutating/output/exec-flag detection, symlink/realpath containment, and report-writer rejects. Rescue, pursue and write-swarm may run `rm`/`mv`/`cp`/`mkdir` with exact flags on absolute in-root non-`.git` operands, never on Windows; one per command; `rm -r`/`mv`/`cp -R` refuse `.git` trees (bounded scan); `.git` matches any case; path spellings the two resolvers can disagree on are refused. Test runners execute repo code by design; internal Git context commands retain the repository-config/helper trust boundary in `docs/safety.md`.
- **No Git mutation.** Rescue cannot mutate Git state; the calling host owns branch and commit decisions.
- **Pursue (experimental).** Runtime-foreground-only autonomous `/goal --` with rescue write policy and hook enforcement on every turn; no Git mutation or resume, default finite 45m budget. Only trusted pursue/root permits exact GetGoal and terminal UpdateGoal complete/blocked; creation/reactivation/budget mutation stays denied. Preserve rescue lineage, immutable operation export, legacy goal flag, and terminal exits 0/3/6.
- **Read-only swarm.** Every worker retains the managed read-only hook; singular `Agent` is denied. Finite budget defaults to 30m; `--cap` stays a soft lifetime-total hint. A bounded row bounds simultaneous Kimi child turns (not the coordinator or OS subprocesses) by `--max-concurrency` (default 4). The hook counts fresh/resumed entries; malformed calls, forks and fresh singleton waves deny. Concurrency 1 uses one direct worker with delegation denied. Immutable policy/width also reach the escape monitor. `KIMI_CODE_SWARM_TIMEOUT_MS=2147483647` overrides ambient values; a stuck child holds its wave until completion or finite whole-job stop. Parallel sessions disable native `TaskStop` after activation shutdown and before print, closing automatic Bash backgrounding; the hook denies explicit background Bash. Identity-verified owned-process settlement gates normal exit and cancellation before artifacts/patch capture. Individual Bash timeout is not a descendant barrier between waves. See §2.
- **Write-swarm is patch-only.** A born-HEAD detached worktree under the data root holds writes while `job.cwd` stays the user workspace; the trusted root confines them and disjoint targets stay prompt guidance. Require hooks, finite budget and dirty-tree warning. Default concurrency 1 is a direct worker on bounded rows; higher values use guarded waves. Older rows serialize normal launches. Capture an untruncated binary patch before cleanup; capture/cleanup failure retains the tree. Never apply/commit or age-delete trees; prefer explicit cancellation. Pursue writes the real workspace.
- **`goal.summary` and retry metadata.** Capture role-less `goal.summary` on `CliClientResult.goalSummary`; model/filter `turn.step.retrying` like other wrapper metadata, while malformed shapes enter diagnostics.
- **Plugin data ownership** (§5): `KIMI_PLUGIN_CC_DATA` is the absolute override. Standard installs derive host-specific paths from the loaded package; conflicting shared values refuse before store access. DSH selects `$DSH_HOME/plugin-data/kimi-plugin-cc` or an absolute override and clears shared host variables. No automatic migration; detached workers pin the selected root and Stop skips visibly on resolution failure.
- **Jobs are authoritative.** SQLite terminal states are permanent. Nullable response budgets and `budget_source` preserve explicit/inherited/default provenance for ask/rescue/review/challenge; pursue/swarm persist effective safety ceilings. Detached workers reload budgets from SQLite; inherited ask/rescue budgets print at launch.
- **Session visibility and titles.** Settled native-v2 sync sets the preview to the run's raw request (redacted, ≤4000 chars, never empty) and invalidates the shared index; preserve manual/native titles and replaceable fallback semantics. Never auto-invoke the native title endpoint. `repair-sessions` previews by default, writes only with `--apply` after a prompt-digest match, replaces only blank or own-prompt previews, and excludes review-gate sessions. See `docs/session-visibility.md`.
- **Model selection.** `--thinking` requests effort through `KIMI_MODEL_THINKING_EFFORT`; omission preserves ambient env and resumes do not inherit. Honoring is unverifiable over stream-json. Omit `-m` for fresh defaults; resumes keep session models; per-run aliases never change saved defaults. `setup --models [--json]` is a credential-safe inventory, not a connection test; never guess aliases or fall back silently. Provider setup stays in `/login` or `/provider`, saved-default changes in explicit `/model`. See `docs/models.md`.
- **Per-call scope.** Only ask/review/challenge/read-only swarm take `--read-root <abs-dir>` and `--network` (MCP `read_roots`/`network`). The hook reads only per-spawn `KIMI_PLUGIN_CC_READ_ROOTS`/`KIMI_PLUGIN_CC_NETWORK`, deleted before every spawn; malformed values fail closed. `--network` allows public-host web tools and confines reads to workspace plus roots; it refuses on uncertified releases and on resumes with unconfined history. Scope is never inherited.
- **Session references.** `--reference-session <id>` (MCP `referenced_sessions`, ≤8) on ask/review/challenge/rescue/swarm appends upstream's exact `<referenced_sessions>` block naming each session's main journal, reading no journal content. Unknown, ambiguous or unsafe ids, the resumed session and legacy-v1 refuse before any job row. A scoped call gains each session's `agents/main` as a read root. Never on pursue, review gate or DSH, nor in summaries, titles or previews.
- **Prose pass-through.** review/challenge/ask/rescue emit raw prose. Only the review gate parses Kimi output, as a disabled-by-default Stop hook that fails open on malformed output/timeout and skips visibly without valid enforcement.
- **LLM-caller discipline.** stderr is for humans; load-bearing results use stdout, exit codes, or SQLite. Unknown flag-shaped tokens fail `INVALID_ARGS`; leading `--help` prints supported usage and exits 0. `RuntimeError.details` carries structured context; CLI errors stay bounded diagnostics and never override lineage/prose/exits. `result <jobId> --json` exposes the structured envelope, budget provenance, and captured session id/source. Launch warnings persist in `warnings` and open stdout and artifacts as a `Warnings:` block; warning-free output is unchanged.
- **Cancellation.** AbortController + SIGTERM → SIGKILL (1500ms), with teardown a settlement barrier. Revalidate PID/PGID/start identities, confirm bounded quiescence, never signal replacements, emergency-kill the owned root on teardown failure; Windows stays direct-child-only. Snapshot failure stops the owned root, then fails with unverified cleanup and its cause; wrapped budgets keep no partial prose. Budgets are finite ≤24h and unaffected by backgrounding. Clean non-aborted exit-0 wins same-tick expiry. Only budget timeouts may retain partial prose and a proven session; cancellation never captures partial output. Preserve `settled_post_abort`, recovery, and lineage gates.
- **Durable swarm recovery.** Record launch intent and verified identities before enabling swarm; store no tokens. `recover-swarm` previews by default; `--apply` recovers only the current repo's stopped owner after identity/session revalidation with the recorded binary still selected, and captures but never applies/deletes the worktree. Terminal outcomes never change; abandoned running jobs fail, never succeed. Normal cancellation launches no recovery; nothing deletes orphans by age alone. See `docs/swarm-recovery.md`.
- **Spawn diagnostics.** Preserve structured process causes; never turn argument/resource exhaustion into reinstall advice. Windows rejects known-overlimit UTF-16 argv with `CLI_COMMAND_LINE_TOO_LONG` and omits the prompt. Print prompts remain argv-backed; no stdin transport or Windows large-review support is implied.

## When editing

- Read the runtime before changing it; several safety invariants are not obvious from file names.
- Run `bun run check` before considering a change done.
- After `runtime/**` or `scripts/*.sh` changes, run `bun run build && bun run generate:surfaces`, then stage `dist/` and both `plugins/` trees, which forbid hand edits: edit source and regenerate.
- `check:surfaces` verifies Claude byte hashes, current Codex/DSH generated text, byte-exact runtime mirrors, and no orphaned generated files. Re-pin Claude bytes in `CLAUDE_SURFACE_HASHES` with `shasum -a 256 <file>` whenever they change.
- Agent definitions register at session start; until the host reloads, use slash commands or `companion.sh` directly.
- **Tests never inherit host plugin env.** `bunfig.toml` preloads `tests/helpers/preload.ts` to delete host root/data and per-spawn overlays. Tests requiring those paths set their own explicitly; dependency directories stay out of test discovery and the preload is never removed.
- Comments state current, non-obvious constraints and change with behavior; history goes in the changelog/audit log.
- **Changing a contract** requires the full statement in `docs/invariants.md` and its short summary here. Rationale and archaeology belong in owning docs or logs.

## Releasing

Plugin versions use ordinary SemVer and may align with the certified kimi-code version, but the number is never compatibility evidence; state exact certified CLI versions separately. Never reuse a published version/tag or encode an upstream patch with leading zeros. Source audit, exact-binary controls, per-operation smoke, and full check are mandatory. The runtime certification table is authoritative ([docs/invariants.md §2](docs/invariants.md)).

`runtime/version.ts` is the SINGLE version source; `scripts/surface-registry.ts` propagates it to Codex and DSH manifests. A version bump touches:

- `runtime/version.ts`, `package.json`, `.claude-plugin/plugin.json`, and `.claude-plugin/marketplace.json`; re-pin both manifest hashes in `CLAUDE_SURFACE_HASHES`.
- `scripts/surface-registry.ts`: update `DSH_PUBLISH_TIMESTAMP` with the actual publication time; `generate:surfaces` refreshes `dsh/index.json` and its test checks version/timestamp/range.
- `AGENTS.md`: bump the version and REPLACE any changed standing contract in present tense; what a release did belongs in `CHANGELOG.md` or the ROADMAP audit log, mechanics in `docs/invariants.md`.
- `CHANGELOG.md`: add a version section for releases, not docs-only compatibility checkups.
- Run `bun run build && bun run generate:surfaces` and stage all three distributions.

Before release validation, run `bun install --frozen-lockfile`; never reuse an unchecked dependency directory as proof of reproducibility. Regenerate/stage all distributions, then run `bun run check`. Compiled-runtime regressions must execute emitted JavaScript, not only Bun's TypeScript loader.

Commit and push the release commit, wait for CI, then `git tag -a vX.Y.Z -m "..."`, `git push origin vX.Y.Z`, and `gh release create --verify-tag`. Published tags are immutable; fix forward.

### npm distribution

`package.json` allowlists publication files. `bun run check:package` packs the archive, rejects sync-conflict copies, byte-checks all three compiled distributions, and runs isolated setup/check, unsupported-version refusal, and modern/legacy MCP smokes without credentials, live plugin state, or model calls. CI runs it after the full check. `publish.yml` builds/tests a release tag and publishes that exact tarball through npm OIDC in the `npm` environment. See [docs/registry-releases.md](docs/registry-releases.md).
