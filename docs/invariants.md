# Runtime invariants — long form

Release status: plugin 3.1.0 establishes a rolling compatibility window with floor `>= 2.8.0`, certifies exact Kimi Code CLI `2.8.0` for all 7 model operations under the no-plan and bounded-swarm construction ([2.8.0 certification record](upstream-2.8.0-certification.md)), collapses all host interfaces onto 4 MCP tools plus `SEP-2640` skill delivery and 5 primary CLI subcommands, unifies all hosts on one canonical shared data directory and one bundled PreToolUse hook, and packages one repository root across Claude Code, Codex, Antigravity, DeepSeek Harness (DSH), and Magpie.

This document holds the full statement of every contract summarized in [AGENTS.md](../AGENTS.md), with the mechanics and rationale that stop each one from being broken again. `AGENTS.md` stays strictly under 24 KB as the per-turn contract sheet; edit both files together whenever a standing contract changes. Release history lives in [CHANGELOG.md](../CHANGELOG.md).

## 1. Native-v2 safety contract (the version headline)

Version: 3.1.0 (`kimi-code`, subprocess transport, native agent-core-v2).

Every executed tool call in a plugin-managed session passes the managed PreToolUse hook, and the engine's chain-breaking plan-file allow is never armed. At Kimi Code 2.8.0, upstream runs the external hook before the plan guard and no production code calls `event.allow()`, and the live plan-ON control proves the hook denies the plan-file Write (§2 Before-execute channel). MoonshotAI/kimi-code#3431 remains open, so that ordering fix is observed rather than announced. All four no-plan closures therefore stay mandatory on every release as a second layer:

1. Default plan mode preflight: `runtime/native-v2-preflight.ts` reads the default-plan-mode setting under every spelling upstream's loader normalizes to the `defaultPlanMode` domain (`default_plan_mode`, `defaultPlanMode`, and mixed spellings; it mirrors upstream's `snakeToCamel` verbatim, pinned by `tests/audit/v2-tag-scan.test.ts`; the `[experimental]` table keeps raw keys and is not normalized) from the same `<KIMI_CODE_HOME>/config.toml` that the child reads, both before spawn and at the spawn boundary, with `KIMI_CODE_HOME` resolved against the child's cwd on every entry path. Any value other than absent or literal `false` refuses (`CLI_V2_PLAN_MODE_CONFIGURED`, remedy: edit the config key, never run setup) except on a fresh or resumed non-swarm launch of an exact certified row with the `print-cancels-plan` capability (`2.8.0`). There, upstream reads the setting only inside session creation (`sessionLifecycleService.create`; resume never consults it) and a fresh `kimi -p` cancels that create-time enter before any turn (`run-v2-print.ts`), so plan mode is never active when a tool runs. Swarm launches (gated by operation kind, so concurrency 1 included), uncertified releases, and test-bypass plans still refuse; an unreadable config refuses everywhere (`CLI_V2_CONFIG_UNREADABLE`).
2. Plan tool denials: the managed hook denies `EnterPlanMode` and `ExitPlanMode` for every command label (`runtime/hooks/approval-policy.ts`).
3. Resume lineage, plan-taint, and tower-mode scans: resume accepts only proven `native-v2` plugin lineage (`KIMI_SESSION_LINEAGE_UNKNOWN` for unknown rows, `KIMI_SESSION_ENGINE_MISMATCH` for historical `legacy-v1` rows) after a raw scan of every agent `wire.jsonl` for `plan_mode.*` and `plan.*` records (`KIMI_SESSION_PLAN_TAINTED`) — `restore()` folds only that journal, and nothing else can restore plan state. The scan frames each wire journal exactly as kimi-code's replay does (`kimiJournalRecords` in `runtime/kimi-journal.ts`, mirroring `append-log.ts`: LF-delimited, one trailing CR stripped, only empty lines skipped). A terminated line that fails to parse is corruption, and after the first corrupt line no later record can fold a cancelled create-time plan enter. On a `print-cancels-plan` row, a non-swarm resume tolerates exactly one main-agent `plan_mode.enter` followed by its cancel before any activity record in a journal with no rewind record (`agent.switched`, `context.undo`, `context.undone`). Only Kimi's 3 durable MCP bookkeeping records (`mcp.tools_discovered`, `mcp.server_failed`, `mcp.server_failure_resolved`; `PLAN_PAIR_BOOKKEEPING`) may sit between enter and cancel because Kimi's MCP service writes them on its own clock while servers connect and each folds only into MCP discovery or failure state. Any other record or an unparseable line between the two taints, as does an uncancelled enter or that pair anywhere else. The same scan refuses to resume a session whose main journal leaves the main agent in tower mode, folded the way Kimi restores it: a `tower_mode.enter` with no later `tower_mode.exit`, counting only records with no `agentId` or `agentId: "main"`; a complete unparseable line naming a tower record counts as an enter, a torn final line is ignored, and an exit after a corrupt line does not clear the state because Kimi stops replaying there (`KIMI_SESSION_TOWER_ACTIVE`, `refusal_kind: "session-tower-active"`). Restoring such a session can adopt the workspace's `.tower/comms` state without a tool call regardless of the tower flag (`towerService.ts` `reconcileForeignTower`). The remedy is turning tower mode off in that session with `/tower`, or starting a fresh session; nothing saved is modified.
4. Experimental selector forcing: tower and subagent fork stay off. Every print and web child receives `KIMI_CODE_EXPERIMENTAL_TOWER=0` and `KIMI_CODE_EXPERIMENTAL_SUBAGENT_FORK=0`, because per-flag environment values outrank both `[experimental]` config and the master flag upstream (`app/flag/flagService.ts`), and a native-v2 child never receives `KIMI_CODE_EXPERIMENTAL_FLAG`. Kimi Code 2.8.0 removed subagent fork and ignores its variable. Enabled selectors therefore do not refuse any native-v2 plan. On a certified or test-bypass plan the forcing is silent. On an uncertified release (`> 2.8.0`), whose flag handling is unreviewed, the child gets the same forcing and the launch carries a warning naming every switched-on selector: every truthy `[experimental]` key and every truthy `KIMI_CODE_EXPERIMENTAL_*` variable, including the master flag (matched case-insensitively on Windows). The plugin changes no other experimental setting, and any tool an experimental feature adds stays outside each label's allowlist (`WaitFor` is explicitly allowlisted). Only a plan-less launch refuses a truthy `[experimental] tower`/`subagent_fork` or per-flag variable (`CLI_V2_EXPERIMENTAL_UNSAFE`; an uncertified launch also gets that code when the config cannot be read), and only a plan-less launch refuses a truthy master flag (`CLI_V2_HOOK_ORDER_UNSAFE`).

Local execution is mandatory. A configured `[environments] default` refuses (`CLI_V2_ENVIRONMENT_UNSAFE`) except on a fresh or resumed non-swarm launch of an exact certified row with `local-environment` (`2.8.0`; `allowDefaultEnvironment` from `certifiedPrintLaunchHas` in `runtime/native-v2-preflight.ts`). Upstream reads the default only during session creation (`sessionManagerService.openCreation`): a fresh print passes `--environment local`, which wins over declarations, and a resume applies the session's stored binding instead, which the plugin still requires to be `local` and inside the expected execution root (`KIMI_SESSION_ENVIRONMENT_UNSAFE`). Swarm launches and any launch without an exact certified row (an uncertified release or plan-less launch) still refuse `[environments] default`. A non-table `[environments]` refuses everywhere. `[workspace] require_trust = false` is the user's choice and emits the launch warning `Workspace trust is disabled in kimi-code's config: MCP servers configured by this repository can start outside the plugin's hook.`; a non-boolean value or non-table `[workspace]` refuses (`CLI_V2_WORKSPACE_TRUST_UNSAFE`). Launcher `--environment` and `--environment-cwd` selectors are reserved (`INVALID_ENV`). Fresh `>= 2.8.0` print passes `--environment local` (certified and uncertified read-only alike); resume never receives that flag; preflight rejects persisted nonlocal or wrong-root metadata or binding records against the expected execution root.

Certification is per exact version and per operation (`NATIVE_V2_CERTIFIED` in `runtime/kimi-engine.ts`). A new kimi-code version is added to `KIMI_V2_RELEASES` only after `tests/audit/v2-tag-scan.test.ts` passes against its source tree, the plan-ON live control confirms the hook denies the plan-file Write, and per-operation real-binary smoke passes. Every native-v2 plan requires `{"role":"meta","type":"system.version","version":<probed>}` as the first stream-json line matching the probed version (`CLI_ENGINE_PROVENANCE_MISMATCH` tears down the process tree before any record is delivered). `Bash.cwd` is validated against the trusted root before the command string (`runtime/rescue-approval.ts`) because the hook payload's top-level `cwd` is the process cwd, not the Bash cwd. Active certification evidence lives in [upstream-2.8.0-certification.md](upstream-2.8.0-certification.md).

Hook-pin durability contract: the canonical hook command must never embed a version-stamped Node token. `preferStableNodePath` prefers `process.argv0` over `process.execPath` only when it is absolute and `realpath`-identical. `verifyHookInstalled` runs `access(nodeBin, X_OK)` fail-closed and checks script readability; `nodeBin` is parsed back from the built command (`parseHookShellCommand`), never re-resolved. That check covers the case where config and expected command are byte-equal yet the embedded Node token fails `X_OK` (`refusal_kind: "node-bin-not-executable"`, whose remedy is repairing Node rather than running setup). Re-pin-recoverable refusals carry `drift` and `hookRefusalDetails`; callers run `scripts/companion.sh setup` (or `kimi_setup({ action: "install" })`) and retry once only when `retryable_after_setup` is literally `true` and setup exits 0 (`hookRefusalRetryProtocol` in `runtime/hooks/install.ts`). When `KIMI_PLUGIN_CC_DATA` is set while the installed block points at the default shared canonical hook, verification still fails closed, sets `dataOverrideFromCanonical: true` and `retryable_after_setup: false`, and instructs unsetting `KIMI_PLUGIN_CC_DATA` and restarting the host instead of re-pinning the shared block. Startup-failure wraps thread `availability`, `cause_code`, and `cause_message` into `details`; `auth.login_required` classifies to `*_KIMI_AUTH_UNAVAILABLE` with a `kimi login` remedy. In-verifier auto-repin is rejected — never re-propose it.

Background-worker test discipline: detached-worker hook-enforcement tests must run the companion CLI as a real `node` subprocess through a symlink with no `KIMI_PLUGIN_CC_NODE_BIN` override and no `KIMI_PLUGIN_CC_SKIP_HOOK_CHECK` (`tests/runtime/background-hook-enforcement.test.ts`).

Smoke-home representativeness: any real-binary smoke case must assert its own precondition when the behavior under test depends on host state. Never write a "plan-file write is denied under plan mode" smoke inside a managed run where plan mode is never armed — that would pass vacuously.

### Hook-escape monitor (detection evidence)

`runtime/hook-escape.ts` replays the pure hook policy (`decideHookOutcomePure`) on every streamed `tool_calls` entry in `cli-client.ts`. A call the policy denies whose tool result does not match the managed hook's denial is recorded as `mismatch` (retaining a 200-character excerpt for triage), and a denied call still without a result at settlement is recorded as `unresolved`. Each tool-call ID is reported at most once. An absent or empty command label is inert.

A tool record clears a pending denial when `carriesDenial(content, reason)` holds: byte-equal content, or the denial reason followed only by upstream repeat-breaker `\n\n<system-reminder>...</system-reminder>` blocks (`agent/toolDedupe/toolDedupeService.ts`). Because releases before `2.8.0` are removed, the pre-2.6.0 handoff-veto text exception (`emitsHandoffVeto`) is removed too. Malformed JSON arguments and non-plain objects normalize to `{}` to match upstream hook input normalization; filesystem-evaluator markers are ignored rather than re-evaluated after execution.

Findings are detection evidence, never a failure: logged as `event: "hook_escape"`, persisted in the `hook_escapes` JSON column (`observedExecutionFields`), exposed by `job status`, `job result --json`, and `kimi_job`, printed as a stderr `safety hook notice`, and carried in `error.details.hook_escapes` on budget timeout. Print mode writes tool results without an outcome field, so a mismatch can equally represent an upstream pre-hook rejection (unknown tool, disabled tool, invalid args, sensitive path `PathSecurityError`, or per-tool resolve errors), a coexisting hook or permission policy blocking first, or a cancel/budget abort landing before the result. Failing a job requires positive execution evidence (tracked upstream in MoonshotAI/kimi-code#4241). Streamed calls under read-only labels and pure denials under write labels (plan and goal tools) are covered; in-process swarm subagent calls do not reach the coordinator's stream.

## 2. Upstream compatibility and the native-v2 contract

Release numbering: plugin versions advance independently of upstream using ordinary SemVer. A plugin release may align with a certified kimi-code version, but the number is never compatibility evidence — state exact certified CLI versions separately. Never reuse a published version or tag, and never use leading-zero patches. Source audit, exact-binary controls, per-operation smoke, and full `bun run check` must pass before extending `KIMI_V2_RELEASES`.

Rolling compatibility window (`>= 2.8.0`): `KIMI_V2_RELEASES` in `runtime/kimi-releases.ts` holds one row per exact certified release, carrying its upstream commit, scope (`"all"` or `"non-swarm"`), and re-proven capabilities (`hook-schema`, `web-preactivation`, `print-cancels-plan`, `local-environment`, `agent-state`, `modern-ws-control`, `bounded-swarm`, `web-json-ready`). `KIMI_MINIMUM_CERTIFIED_VERSION` (`runtime/kimi-version-probe.ts`) equals the lowest row (`2.8.0`). Every version-gated branch asks `resolveKimiRelease`, `kimiReleaseHas`, or `kimiCertifiedReleaseHas`; no branch spells its own version list.

- Certified floor: exact `@moonshot-ai/kimi-code@2.8.0` (commit `46d9085f37c1b145ccfc82a24387e26aa940e94f`, scope `"all"`) is certified for all 7 model operations (`ask`, `review`, `challenge`, `rescue`, `pursue`, `swarm`, `swarm-write`). Evidence: [docs/upstream-2.8.0-certification.md](upstream-2.8.0-certification.md).
- Removed releases: releases below `2.8.0` — both `legacy-v1` (`0.1` to `0.41`) and earlier `native-v2` rows (`0.42` to `2.7.x`) — are removed and refuse before spawn (`KIMI_CAPABILITY_NOT_CERTIFIED`, `refusal_kind: "legacy-v1-unsupported"` or `"v2-version-not-certified"`). `selectIntendedEngine` always selects `"native-v2"`; historical `legacy-v1` rows remain readable in SQLite (`status`, `result`, `replay`) and cannot be resumed.
- Exports: `NATIVE_V2_CERTIFIED_VERSIONS` is the all-operation export (`["2.8.0"]`); `NATIVE_V2_NON_SWARM_VERSIONS` is `[]` (retained for compatibility); `NATIVE_V2_ANY_OPERATION_VERSIONS` is the scoped union.
- Hook schema: `runtime/hooks/config-safety.ts` accepts the 13 base hook events (`PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `UserPromptSubmit`, `Stop`, `StopFailure`, `SessionStart`, `SessionEnd`, `SubagentStart`, `SubagentStop`, `PreCompact`, `PostCompact`, `Notification`). Additive version-sensitive events (`PermissionRequest`, `PermissionResult`, `Interrupt`) require an exact certified `>= 2.8.0` row with the `hook-schema` capability. Unlisted `2.y.z` releases, pre-releases, and other majors fail closed for those events; an uncertified release never borrows `hook-schema`.

Load-bearing native-v2 facts re-verified on each audit ([docs/upstream-compat-audit.md](upstream-compat-audit.md), `tests/audit/v2-tag-scan.test.ts`):

- Engine provenance: every model job persists `operation_kind`, `intended_engine`, `observed_engine`, exact command tuple, probed `kimi_version`, `plan_certification`, `safety_profile` (`native-v2-no-plan/1`), and `resumed_from_job_id`. A native-v2 plan requires `{"role":"meta","type":"system.version","version":<probed>}` as the first stream-json line and tears down the owned process tree on any mismatch before delivering any record. Rescue, pursue, and swarm-write receive their trusted root from `KIMI_PLUGIN_CC_WORKSPACE_ROOT`, never hook payload `cwd`.
- Before-execute channel (`2.8.0`): the executor builds its `starting` chain from `[resetHook, legacyHook, ...hooks, internalHook]` (`agent/toolExecutor/toolExecutorService.ts`, dispatched in insertion order by `packages/core/src/hook/registry.ts`). The external PreToolUse listener runs inside `legacyHook` (`registerLegacyStarting`), ahead of every `registerHook` hook; the plan guard is a `registerHook({ starting })` hook returning `skipPermitting` (`features/plan/planService.ts`), and no production code calls `event.allow()`. One construction site (`session/agentLifecycle/agentLifecycleService.ts`) builds main, subagent, and swarm child scopes, fresh and resumed. The auto-approve gate runs in the later `permitting` phase and can never override a hook veto. All four no-plan closures remain on as a second layer.
- Hook engine (`packages/agent-core-v2/src/features/externalHooks/`): strict `{ event, matcher?, command, timeout? }` config; `internal/runHook.ts` maps exit 2 to deny with trimmed stderr reason, exit 0 + JSON `permissionDecision: "deny"` to deny, and anything else (including spawn error, timeout, abort, bad JSON) to fail-open allow, with a 30-second upstream default; empty/omitted matcher matches all tools, throwing regex matches nothing; `Promise.all` then first block wins. `Write` and `Edit` carry `tool_input.path` (`Write` also `mode: overwrite | append`); `Bash` carries `command`, `cwd`, `timeout`, `run_in_background`. `Bash.cwd` runs without upstream root assertion, so `rescue-approval.ts` confines it before validating the command string. Plugin-contributed hooks append and dedupe on `cwd\0command`; any-block-wins keeps them safe.
- Print mode (`apps/kimi-code/src/cli/v2/run-v2-print.ts`): forces `permission: "auto"` fresh and resumed with `nonInteractive: true`. Consumed argv: `-p` (prompt value), `-r` (alias of `-S`/`--session`), `--output-format stream-json`, `-m`, `--skills-dir`, and `--environment local` on fresh print (`>= 2.8.0`); `--auto`/`--yolo`/`--plan` reject with `-p`; `--environment`/`--environment-cwd` are reserved in launcher prefixes; `--agent`/`--agent-file`/`--add-dir` are never passed. `-r` refuses when recorded session cwd differs from current cwd. Records include assistant/tool messages, meta `system.version`, `session.resume_hint`, `turn.step.retrying`, and role-less `goal.summary`. Every spawn exports `KIMI_CODE_NO_AUTO_UPDATE=1` and an absolute `KIMI_CODE_HOME`, and deletes `KIMI_CODE_TRUST_WORKSPACE`.
- Plan mode arming vectors: `default_plan_mode` (user config only, cancelled on fresh print at `2.8.0`), `EnterPlanMode` (removed at `2.8.0` and still hook-denied), and journal replay on resume (`restore()` folds only `agents/<id>/wire.jsonl`). Not reachable from `-p`: KAP server routes, TUI `/plan`, `--plan`, agent profiles, subagent/tower inheritance, or undo.
- Plugin slash commands: RPC/host-initiated only and absent from `-p`; `-p` intercepts only `/goal`. Read-only operations hard-prefix an instruction line so prompts never begin with `/goal`.
- Custom-agent trust boundary: print mode discovers user, project, and plugin agent profiles (`<git-root>/.kimi-code/agents`, `<git-root>/.agents/agents`) and system prompts; they can steer model intent but cannot set hooks, permission mode, cwd, plan state, or widen the allowlist. Inspect them before running write operations in an untrusted repository.
- Daily monitor reports live under `.claude/kimi-code-research/daily-monitor/` (gitignored); they inform audits but never certify a release.
- Goal mode: triggers on `/^\/goal(\s|$)/` alone; exit codes 0, 3, and 6 mean complete, blocked, and paused; `pursue` is hook-gated on every continuation turn.
- AgentSwarm and subagents: children run in-process in a child DI scope sharing the session workspace, each with its own eager external-hooks service so every child tool call fires the managed hook. Singular `Agent` is denied by every label. `2.8.0` removed `fork` from `Agent` and `AgentSwarm`, and the hook also rejects forks. Native `KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY` can be exceeded during upstream rate-limit recovery, so bounded-swarm wave enforcement (§4) is plugin-owned.
- Background auto-upgrade: out-of-band CLI upgrades on `PATH` are caught by the exact probe before spawn. Jobs prefer the plugin-owned binary from `setup --install-kimi` (§5). `KIMI_PLUGIN_CC_SKIP_VERSION_PROBE` is tests/smoke only.

### Uncertified releases

`resolveKimiRelease` (`runtime/kimi-releases.ts`) and `resolveNativeV2Certification` (`runtime/kimi-engine.ts`) govern unlisted releases:

- Permitted: an unlisted plain `2.y.z` strictly above the `2.8.0` floor runs read-only operations (`ask`, `review`, `challenge`) on native-v2 with `plan_certification = "uncertified"` and launch warning `kimi-code <version> is not certified by this plugin release; running <operation> read-only with <row> mechanics.` (`<row>` is the highest certified row below it, currently `2.8.0`). It borrows only `local-environment` (`--environment local` on fresh print). It never borrows `hook-schema`, swarm/web capabilities, `print-cancels-plan`, or `environments.default` tolerance. Its child still runs with `KIMI_CODE_EXPERIMENTAL_TOWER=0` and `KIMI_CODE_EXPERIMENTAL_SUBAGENT_FORK=0` and without `KIMI_CODE_EXPERIMENTAL_FLAG`, and any switched-on experimental selector produces a launch warning naming every switched-on selector.
- Refused: `rescue`, `pursue`, `swarm`, and `swarm-write` (`KIMI_CAPABILITY_NOT_CERTIFIED`); releases below `2.8.0`; versions with a pre-release or build suffix; other major versions; and every operation when `KIMI_PLUGIN_CC_STRICT_VERSIONS=1` is set. On an uncertified release, `--network`, configured `default_plan_mode`, configured `[environments] default`, and user hooks for `PermissionRequest`, `PermissionResult`, or `Interrupt` also refuse.
- Unchanged: first-line `system.version` verification, managed hook verification, resume journal plan/tower scans, and local-root checks still run.

### Internal process trust boundary

The managed PreToolUse hook gates model tool calls, not every internal subprocess that kimi-code spawns. Repository Git configuration and executables are trusted: Git context commands and POSIX session-lock contention `ps` invocations run with the child's inherited `PATH` and cwd outside PreToolUse. Certification does not claim a hostile-repository sandbox. See [what this safety story does not cover](safety.md#what-this-safety-story-does-not-cover).

## 3. Credential-bearing config

Treat `~/.kimi-code/config.toml` as credential-bearing (it can hold a BYO-provider `apiKey`) and `~/.kimi-code/credentials/` (such as `kimi-code.json`, mode `0600`) as the OAuth token store. For routine status checks, never read, print, copy, or retain raw `config.toml` or anything under `credentials/`; use sanitized `setup --check` or `setup --models [--json]` (or `kimi_setup`).

The model inventory (`runtime/commands/models.ts`) parses config internally and emits only alias, model, and provider identifiers, provider types, default selection, and a secondary-settings presence flag. It never emits keys, headers, environment maps, endpoints, OAuth references, or raw parser errors; never reads `credentials/`; and makes no writes or provider calls. If an explicitly authorized diagnosis requires inspecting `config.toml`, restrict inspection to the plugin-managed hook block and redact all credential material; `credentials/` is never read or copied.

## 4. Runtime invariants

- Session visibility and titles: settled native-v2 sync sets `lastPrompt` (the preview in Kimi Code Desktop and `kimi web`) to the run's raw request (redacted, up to 4,000 characters, never empty; never the prefixed prompt or answer) on fresh and resumed sessions, then invalidates the shared index via `sessions/.index-dirty/<sessionId>.<unique-suffix>`. Session journals, cwd, recency, and unrelated metadata stay untouched. Existing manual/custom titles and native-generated titles are preserved; new fallback titles carry `titleKind: "replaceable"` and `isCustomTitle: false`. The native title endpoint is never auto-invoked. Known race: a Desktop turn finishing between plugin exit and sync has its preview overwritten. `setup --repair-sessions [--apply] [--all]` (and `kimi_setup({ action: "repair_sessions" })`, or alias `repair-sessions`) reads the shared SQLite job database read-only without migrations; default scope is the current repository (`--all` spans all repos in the store). It matches a bounded spawn prompt against `prompt_digest`, previews by default, preserves titles, replaces only blank or verified own-prompt previews, enforces bounded no-follow reads, refuses symlinked directories, publishes atomically with conflict detection, and never calls a provider. See [session visibility](session-visibility.md).
- Model selection: `--thinking <effort>` requests per-run effort via `KIMI_MODEL_THINKING_EFFORT`; omitted flags preserve ambient env and resumes do not inherit. Upstream providers that are not trait-driven silently ignore it, and `stream-json` carries no thinking deltas so honoring is unobservable. `--no-thinking` is rejected; use `--thinking off`. Omit `-m` for fresh defaults; resumes keep their session model; per-run aliases never change saved defaults. `setup --models [--json]` is a credential-safe local inventory, not a connection test; agents never guess aliases or fall back silently. Provider setup stays in `/login` or `/provider`; saved-default changes stay in explicit `/model`. Swarm children may use `[secondary_model]`. See [models.md](models.md).
- Subprocess-first: one `kimi -p` prompt runner per job; certified parallel swarm waves (`--max-concurrency >= 2`) add only the bounded `web --json` activation lifecycle below, never a second prompt transport or model self-activation. Session-id capture is dual-source (`session.resume_hint` meta record on stdout plus anchored stderr UUID announce fallback), first-announce-wins, pinned, and idempotent, with meta records filtered from consumer `records[]`. Captured IDs round-trip verbatim via `kimi -r`.
- Same-job swarm activation (`2.8.0+` parallel waves): upstream removed model-started `AgentSwarm` from fresh print sessions, so `runtime/swarm-activation.ts` starts the exact planned CLI as `web --json` with an in-memory ephemeral token and `KIMI_CODE_SESSION_IDLE_RECLAIM_MS=0`. It validates the loopback origin and `/api/v1/ws` URL, requires exact planned server version and KAP `1.0.0` plus WebSocket capability on authenticated `/api/v1/meta`, creates a session at the canonical swarm/worktree cwd with `environment_id: "local"`, re-reads authenticated `/environment` to prove cwd before profile mutation, binds explicit `-m` or the effective default (`__kimi_env_model__` or redacted `/api/v1/config` `default_model`) with `permission_mode: "auto"` and `swarm_mode: true`, verifies direct WebSocket `subscribe`/`response` main-agent state with plan off through an intentional bounded close, shuts down within 15 seconds, and requires main-journal `swarm_mode.enter` (`trigger: "manual"`). It then disables native `TaskStop` in that fresh stopped session and runs one ordinary `kimi -p -r` print job (`kimi_session_id_source: "preactivated"`, exact session match, first-line `system.version`, and final no-plan checks). After print, a second bounded `web --json` lifecycle rechecks the local binding, sets `swarm_mode: false`, verifies state and `swarm_mode.exit`, and shuts down. Journal reads use `kimiJournalRecords`, where any corrupt line makes state unreadable. Activation consumes the job's finite budget; `runSwarm` solely owns deactivation (remaining budget normally, separate 2-second cancellation-aware failure recovery, never retried; cancellation aborts the owned lifecycle and never starts a cleanup server). Print failures remain primary; post-mutation identity or quiescence uncertainty prevents success and retains raw output, `cleanup_error`, and write worktrees for recovery.

Confined reads reject backslashes, drive letters, symlink escapes, unknown arg keys, `~`, URL schemes, dangling links, `..` globs, and absolute out-of-root globs. `FetchURL` requires `http:`/`https:` without credentials and a public hostname or canonical global unicast IP (rejecting localhost/local/internal names, numeric hosts, private/CGNAT/loopback/link-local/IETF/doc/benchmark/6to4/multicast/reserved IPv4, non-`2000::/3` or IETF/Teredo/doc/6to4 IPv6, and non-global NAT64 embedded IPv4). `--network` refuses on uncertified releases and on resumed `ask` sessions unless every plugin-recorded earlier turn had confined roots within the current call's roots. Scope is stored in `read_scope`, surfaced in `job status` and opening `Scope:` line, never inherited across calls, and limits Kimi's tool reads only (not review diffs or Kimi's own `AGENTS.md` files).
- Session references: `ask`, `review`, `challenge`, `rescue`, `swarm`, and `swarm-write` accept up to 8 distinct `--reference-session <job-id|session-id>` values (MCP `referenced_sessions`); `pursue` rejects them (`INVALID_ARGS`). Resolution (`runtime/session-references.ts`) never reads journal content, validates `sessions/` as non-symlinked with bounded readdir, requires exact stored session ID spelling in exactly one workspace, validates non-symlink components down to `agents/main` inside `sessions/`, opens `agents/main/wire.jsonl` no-follow as a regular file, and appends upstream's exact `<referenced_sessions>` XML block at the very end of the full prompt (never in summaries, titles, or previews). Scoped calls add each referenced session's validated `agents/main` realpath to `read_scope` (covering logs, saved tool outputs, and plans; with `--network`, that content can reach the web). Unknown, ambiguous, self-resumed, or unsafe IDs refuse with `INVALID_ARGS` before any job row.
- Cancellation, POSIX snapshot failure, and timeout session recovery: cancellation uses AbortController + SIGTERM -> SIGKILL (1,500 ms escalation) with teardown as a settlement barrier. On POSIX, detached process-group spawns capture descendant ancestry plus PID/PGID/start-time identities in bounded snapshots (Linux reads `/proc` directly without `ps` fallback; excludes only proven `PF_KTHREAD` with PGID 0), revalidate identities before signaling, start grace after SIGTERM, and wait through 500 ms post-SIGKILL quiescence; changed identities are never signaled; teardown failure emergency-kills the owned root and rejects explicitly. Windows stays direct-child-only. Legacy cancellation snapshot failure stops the owned root and rejects with `CLI_CANCELLATION_TEARDOWN_FAILED` (`process_cleanup_unverified: true`) and its cause (wrapped budgets keep no partial prose); swarm activation web-child tracking retries incomplete snapshots after 5 ms and 20 ms within one 50 ms tick. Clean non-aborted exit-0 wins same-tick budget expiry. Only `ask`/`review`/`challenge`/`rescue` budget timeouts retain settled partial prose under a clearly marked NOT-a-final-answer heading (`partial_output: true`) and either an announced session ID or uniquely matched timeout session recovery (`runtime/session-recovery.ts`: scans `sessions/*/session_*/state.json`, capped at 65,536 entries, 1 MiB state, 4 MiB journal prefix, 64 MiB total, no-follow regular files; requires version 2, realpath cwd match, `createdAt` in `[spawnedAt, settledAt]`, unused session ID in SQLite, exact `prompt_digest` sha256 match on first user message, observed `system.version`, and exactly one candidate). Cancellation never captures partial output.
- Config writes preserve `0600` at creation (`open(..., 0o600)` + `chmod(0o600)` before rename).

## 5. Plugin data ownership

`runtime/plugin-data.ts` and `runtime/paths.ts` resolve one canonical shared data directory for every host (Claude Code, Codex, Antigravity, DSH, Magpie, and direct CLI):

- Explicit override: `KIMI_PLUGIN_CC_DATA`, which must be an absolute non-empty path (otherwise `INVALID_PLUGIN_DATA`). It points to the parent directory under which `kimi-plugin-cc/` lives.
- Test guard: `KIMI_PLUGIN_CC_TEST_NO_DEFAULT_DATA=1` throws `MISSING_PLUGIN_DATA` when `KIMI_PLUGIN_CC_DATA` is unset so tests never touch a developer's real store (`tests/helpers/preload.ts` sets this automatically).
- Default on macOS and Linux: `$XDG_DATA_HOME/kimi-plugin-cc` when `XDG_DATA_HOME` is an absolute path (relative values are ignored per the XDG Base Directory Specification), otherwise `$HOME/.local/share/kimi-plugin-cc`.
- Default on Windows: `%LOCALAPPDATA%\kimi-plugin-cc` when `LOCALAPPDATA` is set (must be absolute, else `INVALID_PLUGIN_DATA`), otherwise `%HOME%\AppData\Local\kimi-plugin-cc` (or `%USERPROFILE%\AppData\Local\kimi-plugin-cc`).

Inside `<pluginRoot>` (`<dataRoot>/kimi-plugin-cc`; `ensurePluginPaths` creates and sets mode `0700` on POSIX for `pluginRoot`, `logs/`, `artifacts/`, and `hook/` without modifying parent `dataRoot` permissions):

- `state.db`: authoritative SQLite job and `mcp_tasks` database shared across all hosts
- `logs/`: mode `0700` directory holding per-job stream-json logs (`0600`) and MCP child logs (`0600`)
- `artifacts/`: mode `0700` directory holding rendered markdown output and write-swarm `.patch` files
- `hook/`: symlink-verified mode `0700` directory holding `package.json` (`{"type":"module"}`, `0644`) and the staged, probed, atomically activated bundled `approval-hook.js` (`0644`)
- `worktrees/`: lazily created ephemeral born-HEAD Git worktrees for `swarm-write`
- `kimi-bin/`: plugin-owned exact Kimi CLI installs (`<version>/` and `current` symlink)
- `config.json`: reserved plugin config path

Per-host environment variables (`CLAUDE_PLUGIN_DATA`, `PLUGIN_DATA`, `$DSH_HOME/plugin-data/kimi-plugin-cc`) are no longer read by `resolvePluginDataRoot`, eliminating multi-host store splits and `PLUGIN_DATA_CONFLICT` errors. No resolver path copies, moves, merges, or deletes old 3.0 per-host state; operators who need an older store can point `KIMI_PLUGIN_CC_DATA` at its parent directory. Detached workers and supervised `mcp-child` processes receive the parent's resolved root via `KIMI_PLUGIN_CC_DATA` so cwd changes cannot redirect their store.

### Plugin-owned kimi-code binary

`setup --install-kimi [--json]` (and `kimi_setup({ action: "install_kimi" })`) installs the highest version in `NATIVE_V2_CERTIFIED_VERSIONS` (`2.8.0`) into `<pluginRoot>/kimi-bin/<version>/` and points `kimi-bin/current` at it (`runtime/commands/setup.ts`, `resolveKimiBinDir`). It stages `npm install --prefix <staging> --no-global --ignore-scripts --no-audit --no-fund --no-update-notifier --save-exact @moonshot-ai/kimi-code@<version>` with a 300-second timeout and `npm_config_global`/`location`/`prefix` cleared, verifies containment (`realpath` inside `<realpath(kimi-bin)>/<dirName>/`, regular file, `X_OK`, exact `--version` match) before renaming into place and atomically swapping `current`. Failures leave `current` untouched. Verified installs reuse without network access; stale `.staging-*` directories older than 11 minutes clean up on next install; old versions stay untouched and `setup --uninstall` leaves `kimi-bin/` intact. Only this command uses the network (unsupported on Windows: `KIMI_INSTALL_UNSUPPORTED_PLATFORM`; other errors: `KIMI_INSTALL_FAILED`, `KIMI_INSTALL_VERIFY_FAILED`).

Binary order (`selectKimiBinary` in `runtime/kimi-command.ts`): `KIMI_PLUGIN_CC_KIMI_BIN`, then plugin-owned `kimi-bin/current` (when verified inside `kimi-bin/<x.y.z>/`), then `kimi` on `PATH`. Because all hosts share `<pluginRoot>`, one `--install-kimi` serves every host. `setup` and `setup --check` report the selected binary on the `Kimi binary:` line and warn if the plugin-owned binary is behind or rejected. `recover-swarm` refuses if the selected binary no longer matches the recorded one.

### Structured print-mode refusals

Kimi Code emits a role-less `{ type: "error", code, message, details }` record for an occupied session and exits 4 without stderr. The parser retains bounded `code` (200 chars) and `message` (4,000 chars) on `CliClientResult.cliError` (first wins), discards holder metadata and session IDs, never puts it in prose or session lineage, and exposes it on `CLI_NONZERO_EXIT.details.cli_error`.

### Durable swarm recovery and spawn diagnostics

Parallel swarm runs maintain a separate SQLite recovery record independent of immutable terminal job outcomes. Launch intent precedes spawn; verified identities follow observation; session/workspace identity and cleanup intent commit before enabling swarm mode. No token, credential, raw config, or prompt enters this record. Stale-job sweeps skip recovery-owned rows; cancel revalidates recorded identities.

`job recover-swarm <job-id>` (or `kimi_job({ action: "recover_swarm" })`) previews by default; `--apply` requires this repository, the recorded home and workspace, a dead original owner, and an atomic identity-bearing claim. It stops only revalidated processes, runs one bounded deactivation with the recorded certified binary and verified hook, captures an untruncated patch without applying or deleting the worktree, marks abandoned running jobs failed, and never alters terminal outcomes or deletes orphans by age. See [swarm-recovery.md](swarm-recovery.md).

CLI spawn diagnostics preserve structured `spawn_code`, `spawn_errno`, and bounded `spawn_message`. Resource errors (`E2BIG`, `ENOMEM`, `EMFILE`) get process-error advice rather than install remedies. Windows preflight counts UTF-16 command-line units including quoting and terminator and refuses values over 32,767 with `CLI_COMMAND_LINE_TOO_LONG` without leaking prompt text. Print prompts stay argv-backed.
